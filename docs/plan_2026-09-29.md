Why: Railway's web app (www.steve-newman.com) was running until it was stopped on 28 Sep.
If a volunteer used it by mistake, those passports exist only on Railway, and their ticket
numbers may clash with Krystal's.

Railway's database has no public address, so check from inside Railway. In **Command
Prompt**, in the repo folder:

```
railway ssh -s Postgres
psql -U postgres -d railway
```

(If psql says the role or database doesn't exist: `env | grep -E "PGUSER|PGDATABASE"` and
use those names.) Then paste this read-only query. It counts **28 Sep** because it's run the
next day:

```sql
SELECT
  (SELECT count(*) FROM passports_passportsubmission) AS total_submissions,
  (SELECT count(*) FROM passports_passportsubmission WHERE (created_at AT TIME ZONE 'Europe/London')::date >= DATE '2026-09-28') AS created_since_28_sep,
  (SELECT count(*) FROM passports_passportsubmission WHERE (updated_at AT TIME ZONE 'Europe/London')::date >= DATE '2026-09-28') AS updated_since_28_sep,
  (SELECT max(created_at) AT TIME ZONE 'Europe/London' FROM passports_passportsubmission) AS latest_created,
  (SELECT count(*) FROM auth_user WHERE (last_login AT TIME ZONE 'Europe/London')::date >= DATE '2026-09-28') AS logins_since_28_sep;
```

Stay in psql for step 2.

- ✅ **Done when:** `created_since_28_sep` and `updated_since_28_sep` are 0.
- If either isn't 0: **stop and bring the output to Claude** before anyone acts on it.
  Those passports would need moving to Krystal without clashing ticket numbers (see
  "Handing back to Krystal" in [railway_fallback.md](railway_fallback.md)).
